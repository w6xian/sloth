# sloth v4.2.0

本次发版带来三块新能力：**方法自省 `_.Funcs`**、**媒体代理（HTTP 隧道）示例与 HTTP 大文件处理**，以及 **TCP / QUIC 客户端断线自动重连**。

## 新增

### 1. 方法自省：`_.Funcs`

每个 `*Connect`（服务端 `ServerConn`、客户端 `ClientConn` 一样）在建实例时自动注册元服务 `_`，对端可随时读取这一侧注册了哪些服务、每个方法的入参与返回值：

```go
data, err := client.Call(ctx, "_.Funcs")          // 读服务端的方法清单
data, err := server.Call(ctx, userId, "_.Funcs")  // 读某个客户端的方法清单
```

- 返回体是 MCP `tools/list` 形态，可直接喂给 MCP client；
- 方法名**大小写敏感、精确匹配**，写 `_.funcs` 只会得到 `ErrMethodNotFound`；
- 入参是位置参数（`arg0` / `arg1`…），`error` 在返回值里如实列出，`description` 放 Go 类型名；
- **只忽略第一个 `ctx context.Context`**（框架注入），后续若还有 context 参数则照实列出；
- 清单不含 `_` 自己；业务自己注册 `_` 会拿到 `service _ already registered`。

### 2. 媒体代理：把内网 HTTP 服务暴露到公网

新增 `examples/media`（服务端 HTTP 网关 + 内网客户端），不新增帧、不新增协议——**一次 RPC 承载一个完整的 HTTP 报文**，Range / 206 / MIME / 304 全部交给客户端本地的 `http.FileServer`：

```
浏览器 ──HTTP──▶ 服务端网关(:8080)
                  ① 请求报文序列化（req.Write）
                  ② server.Call(ctx, userId, "http.Do", raw)
                                ─────▶ 客户端 http.ReadRequest → 本地 http.FileServer
                                ◀────── 响应报文（裸字节）
                  ③ http.ReadResponse → 原样写回
```

实测：`/m/media/wallpaper.jpg` → 200 + `Accept-Ranges: bytes`；`-r 0-1023` → **206** `Content-Range: bytes 0-1023/393630`；未登记的服务名 → 404。

边界（也是方案前提），详见 [media-proxy.md](media-proxy.md) 与 [media-http.md](media-http.md)：

| 方向 | 载体 | 上限 | 结论 |
|---|---|---|---|
| 请求报文 | 入参（ag 编码） | 单参数 65535 字节 | 只放请求头 → 只转发不带 body 的 GET |
| 响应报文 | 返回值（fn 帧裸 payload） | 1GB | 一个 206 分片绰绰有余 |

因此**走 tcp / quic，ws 不适合**（ws 还有 `DataSlice` 分片，单片 65535 且带 JSON 膨胀）。网关目前**没有鉴权**，对外暴露前必须自行加（token 或带 `exp` 的签名）。

### 3. TCP / QUIC 客户端断线自动重连

TCP 与 QUIC 客户端现在共用同一套重连循环（`nrpc.ServeReconnect`）：

- 首次拨号**同步**返回 error（语义不变，调用方据此决定退出还是继续跑）；
- 之后后台按 **500ms → 30s 指数退避（带 ±25% 抖动）** 重拨；连上后被断掉则立刻重连；
- 服务端重启、网络抖动对客户端自动恢复，不再需要业务自己轮询；
- 新增指标：`sloth_tcp_client_reconnects_total`、`sloth_quic_client_reconnects_total`。

> **重连只恢复"连接"，不恢复"会话"**：身份会自动补到新连接上，但服务端 bucket 里的 channel 必须业务在 `OnReady` 里重新 Sign/Reg 才会更新（且不能在 `OnReady` 里同步发 RPC，读写泵还没跑起来会等不到回包，应另起 goroutine）。

QUIC 侧的两个附带修正：握手与 `OpenStreamSync` 各算一份超时预算（过去共用一个 ctx，握手耗掉 9.9s 会让开流只剩 0.1s）；拨号返回后检查关闭信号，避免 `Close()` 之后残留无人管理的连接。

## 修复

- **`meta` 头在多服务场景下是错的**：`Register` 的第三个参数（服务描述）以前是单个字段，注册第二个服务就把第一个覆盖掉。现在按服务名存，并且出现在 `_.Funcs` 每个 tool 的 `description` 里。
- **`ref` 参数清单漏算**：候选方法的参数列表现在只忽略第一个 `context.Context`（框架注入），业务自己声明的 context 参数不再被吃掉。

## 升级注意

- 无破坏性 API 变更，现有代码可直接升级。
- 若业务此前自行注册了服务名 `_`，现在会注册失败（内置自省服务优先）；换名即可。
- 升级后 TCP / QUIC 客户端会**自动重连**：请确认 `OnReady` 里的 Sign/Reg 是幂等的，否则服务端反调可能打到旧连接上。

完整示例：`examples/ws`、`examples/tcp`、`examples/quic`、`examples/media`、`examples/multi`。
