# sloth v4.2.4

p2p 直连（框架内置 NAT 打洞）。

之前两个节点的互通只有两条路：都连云端走服务器中转，或者部署 tunnel v1 的
relay/agent——后者也过云。大量真实场景是**两端都在 NAT 后**（家里的设备、
公司内网的机器），它们之间明明一跳可达，流量却要绕公网一圈。本版把打洞做进
框架：信令经云端 coordinator 牵线，数据在两端直连 UDP，**业务代码一行不改**。

## 用法

```go
// 服务端（被连端，NAT 后）：多带两个选项，其余与普通监听完全一样
drpc.Listen(ctx, sloth.QUIC, "0.0.0.0:8992",
    option.WithCoordinate(sloth.Coordinator(sloth.WS, "coord.example.com:9100")),
    option.WithCoordinate(sloth.Coordinator(sloth.UDP, "coord.example.com:9101")),
    option.WithWorkID("work-xxxx", token),
    option.WithTcpHandleMessage(&Handler{}))

// 客户端（主动端，NAT 后）：地址写成 "对端ID@coordinator地址"
newConnect.Dial(ctx, sloth.QUIC, "work-xxxx@coord.example.com:9100")
```

`@` 语法就是全部变化：识别到 `@`，框架先匿名登记 coordinator、请求牵线、
打洞，然后在打洞的那条 socket 上做 QUIC 握手——对上层完全同构，
`Register`/`Call`/服务端反向推送的写法与直连云端一字不差。打不通
（Symmetric NAT）`Dial` 返回 `p2p.ErrPunchFailed`，上层可回落云端中继。

## 新增

### 1. `p2p` 包：纯打洞引擎

`Establish`（登记 + 地址观测）/ `PunchOut`（探针直到收到对方）/ `WatchIntros`
（服务端等牵线）/ `Keepalive`（REG 心跳保活）。信令面抽象为 `Signaler`
接口注入——本包不 import 任何传输，纯逻辑、可独立测试。

### 2. 根包 `p2p_signal.go`：sloth ws 实现信令

`punchSignaler` 实现 `Signaler`（`punch.Register/Connect` RPC + Intro 推送，
TLV 编解码 + JSON 信封解封，复用 tunnel 已踩平的恒等 codec 坑位）。ws 断线
自动重连并重新登记；直连是独立 UDP，不受信令断线影响。

### 3. option 新增 `WithCoordinate` / `WithWorkID`

- 多次 `WithCoordinate` 是**追加**（ws + udp 两条坐标都留下），不是覆盖；
- 走可选接口（`SetCoordinates`/`SetWorkID`），未实现的传输静默忽略——
  与 `WithTcpHandleMessage` 同一套路；
- `Coordinate` 类型从根包移入 option 修 import 环，根包保留
  `sloth.Coordinator(...)` 别名，对外写法不变。

### 4. 传输层衔接：QUIC 复用打洞 socket（本版核心）

NAT 映射绑定在 socket 上——**换了 socket 换了映射，对方的包永远进不来**。
因此：

- `Listen` 带 `WithCoordinate` 时不再 `net.Listen`，先打洞拿到 UDP socket，
  经 `PacketConnListenerFactory.MakeListenerFromPacketConn` 直接在这条
  socket 上 `quic.ListenPacketConn`；
- `Dial` 走 p2p 时经 `QuicClient.SetPunchedConn` 注入 socket，
  `quicgo.Dial(ownConn, remote)`——QUIC 握手与后续重连都复用同一条
  socket（QUIC keepalive 顺带刷新 NAT 映射）；
- 引擎的读窗口（Establish/PunchOut 收 ACK/探针）结束后才把 socket 交给
  Transport 接管；之后 p2p 只**写**不读（REG/探针纯写，不与 QUIC 抢读）。

目前只有 QUIC 支持（`PacketConnListenerFactory` 扩展点）；KCP 等传输实现
同一接口即可接入。

### 5. coordinator 升级（tools/tunnel/examples/p2p）

| 能力 | 说明 |
|---|---|
| 生成 ID | `punch.CreateID` RPC / `coordinator -create 备注` CLI，产出 `work-<hex>` + token（只显示一次） |
| 管理 ID | `punch.List`（台账 + 在线状态） |
| 鉴权 | 台账内 id 必须携带 token（sha256 入库 + 常数时间比较）；空 id 分配一次性匿名 `anon-<hex>` |
| 离线判定 | ws 断开立即离线；REG 心跳 30s 超时兜底 |
| 持久化 | `-store ids.json` 原子写，重启不丢；**不带 `-store` 只存内存** |
| 兼容 | `regResp` 带完整 `coord_udp`；框架侧对旧版缺主机的回传地址自动补齐 |

**旧版 coordinator 必须重新部署**：旧版无鉴权，任何人可用任意 `-id` 占坑；
且 `regResp` 回传原始参数（`:9101` 缺主机）——框架已做兼容，但安全面只能靠升级解决。

### 6. 示例与文档

- `examples/p2p/`：p2p 版三端样例（`main.go` 服务端 + `client/`），README 含
  完整部署步骤与成功日志特征；
- `doc/p2p.md`：原理与执行流（三端角色、时序图、状态机、UDP 线上协议、
  关键设计点）；
- 旧的三端 UDP 文本聊天 demo（`tools/tunnel/examples/p2p/peer`）删除，
  由框架内置 p2p 取代。

## 验证

本地三端 e2e（coordinator + server + client）：打洞 → QUIC 握手 → `Sign` +
`v1.Test` 每 2s 循环调用成功，coordinator 在 `peers introduced` 之后零数据
流量。客户端直连地址 = 服务端监听端口（8992），证明 QUIC 确实跑在打洞的
那条 socket 上。公网实测：家庭宽带 NAT 后两端直连成功，观测地址
`observed=公网IP:端口` 与直连端口一致。

## 局限（务必清楚）

- 锥型 ↔ 锥型（家庭宽带大多属于此类）可直连；任一侧 Symmetric NAT
  （手机热点、部分公司网）或禁 UDP 即失败，`Dial` 报
  `p2p.ErrPunchFailed`——**回落云端中继**（tunnel v1 relay/agent）是下一步，
  语法不变，框架内部切换；
- 样例 TLS 为自签 + `InsecureSkipVerify`，等于放弃身份校验；生产请用正式
  证书，或让 coordinator 作信任锚校验证书指纹（Tailscale 的做法）；
- 打洞成功后的会话无保活探测，NAT 映射过期后需重新牵线。
